# ChatPulse — настройка индивидуальных Telegram API-ключей

## Для пользователя

1. Запустите ChatPulse и заполните имя на первом шаге.
2. На шаге «Telegram» откройте **«Как получить API ID и API Hash?»**.
3. Авторизуйтесь на https://my.telegram.org и откройте **API development tools**.
4. Если приложение ранее не создавали, создайте его; сохраните выданные **App api_id** и **App api_hash**.
5. Введите API ID (число) и API Hash (32 шестнадцатеричных символа) в ChatPulse.
6. Нажмите **«Сохранить ключи»**. После этого появится экран ввода номера Telegram.
7. Подтвердите вход своим номером +7, кодом и паролем 2FA при необходимости.

Один пользователь получает собственные ключи; другие участники не должны их использовать.

## Где хранятся данные

- `%LOCALAPPDATA%\ChatPulse\settings.json` — имя и этап онбординга, **без секретов**.
- `%LOCALAPPDATA%\ChatPulse\Data\telegram.api.dpapi` — личные API-ключи, Windows DPAPI (CurrentUser).
- `%LOCALAPPDATA%\ChatPulse\Data\telegram.session.dpapi` — личная Telegram-сессия, Windows DPAPI (CurrentUser).
- API-ключи **больше не читаются из переменных среды**.

Ключи не включаются в сборку или распространяемые архивы. При смене API-ключей
старая локальная Telegram-сессия сбрасывается и потребуется повторный вход.

Шифрование DPAPI защищает данные при хранении, но не от процессов, которые уже
работают с доступом к той же учётной записи Windows.

## Техническая организация

- `SaveTelegramApiCredentialsCommand` проходит FluentValidation через
  `CommandValidationDecorator`. Хендлер **не дублирует** входные проверки.
- `GetTelegramApiStatusQuery` определяет наличие настроенных ключей.
- В `WTelegramAuthenticationClient` параметры поступают из защищённого хранилища,
  а не из переменных среды.
- Сохранение шага Telegram остаётся в `settings.json`; отдельный подэтап ключей
  вычисляется из их наличия и не дублируется в Settings.
- UI остаётся на втором шаге после сохранения ключей и открывает форму телефона.

## Проверка в Visual Studio

1. Запустить проект с **пустым** хранилищем, перейти на шаг Telegram: появятся два поля API.
2. Ввести неверный API ID или Hash: ошибка валидации, форма телефона не появляется.
3. Ввести корректные по формату параметры: появляется поле телефона.
4. Закрыть приложение и открыть снова: шаг Telegram восстанавливается, ключи не запрашиваются.
5. Нажать «Изменить API-ключи»: форма позволяет заменить их; сессия будет сброшена.
6. Открыть инструкции: под модальными окнами работает затемнение, после закрытия исчезает.
7. Убедиться, что секретов нет в `settings.json` и логах. Не публиковать `*.dpapi`.

**Ограничение:** валидатор проверяет формат, но не подлинность ключей Telegram.
Реальное подключение проверить только после получения настоящих ключей.
